# 우리 동네 상권분석

소상공인시장진흥공단 **상가(상권)정보 OpenAPI**(공공데이터포털) 실데이터로, 지역(시·도/시·군·구/행정동)
또는 반경(최대 2,000m) 안의 점포 밀도·업종 분포를 확인하는 로컬 웹앱.

`franchise-registry`(가맹사업 브랜드 레지스트리)와는 완전히 별개 프로젝트입니다 — 후자는 브랜드
단위 가맹점 수·매출액을, 이 프로젝트는 **지역 단위 상권 데이터**(어떤 동네에 어떤 업종이 몇 개
있는지)를 다룹니다. 서로 다른 공공데이터 API·서비스키를 씁니다.

```
상권분석/
├── (251128)소상공인시장진흥공단_상가(상권)정보_OpenApi 활용가이드/   공식 활용가이드 원본(참고용)
├── backend/          Express 서버 — 상권정보 API를 대신 호출해 정형 JSON + 집계로 변환. 로컬 개발은 항상 여기서.
├── frontend/         backend가 그대로 서빙하는 정적 웹페이지 (HTML/CSS/JS, 빌드 불필요)
├── api/index.js      Vercel 배포용 — backend/server.js를 그대로 re-export하는 서버리스 함수 진입점
├── vercel.json        모든 요청을 위 함수로 라우팅
└── package.json       Vercel이 저장소 루트에서 npm install할 때 쓰는 설치용 파일(로컬 개발엔 안 씀 — 아래 "Vercel 배포" 참고)
```

## 실행

```bash
cd backend
npm install          # 최초 1회
npm start            # http://localhost:8788 에서 백엔드 + 프런트엔드 함께 실행
```

브라우저에서 **http://localhost:8788** 열면 끝. 단, `backend/.env`에 서비스키를 넣기 전까지는
지역·반경 분석(실API 호출이 필요한 기능)이 전부 502 오류를 반환합니다 — 화면 우상단 배지가
"서비스키 없음"이면 아직 안 된 상태입니다.

### 서비스키 발급 (필수, 아직 없음)

1. https://www.data.go.kr/data/15012005/openapi.do 에서 **활용신청**
2. 마이페이지 → 오픈API → 인증키발급현황에서 **일반 인증키(Decoding)** 값을 확인
   (※ "인증키(Encoding)"가 아니라 **Decoding** 값을 넣어야 합니다 — 이미 퍼센트 인코딩된
   Encoding 키를 넣으면 서버가 한 번 더 인코딩해서 이중 인코딩 오류가 납니다)
3. `backend/.env`의 `SEMAS_SERVICE_KEY=` 뒤에 붙여넣기
4. 서버 재시작 (`npm start`)

개발계정 기준 보통 즉시~수십 분 내 자동 승인됩니다(운영계정으로 트래픽을 늘리려면 별도 심사 필요).

### 지도 API 발급 (선택 — 없어도 좌표 산점도로 위치 확인 가능)

"위치 분포" 카드에 실제 지도를 띄우고 싶으면 **네이버 지도 JavaScript API v3** 키가 필요합니다.
없어도 앱은 정상 동작하고(좌표 상대 위치 산점도만 나옴), 나중에 아무 때나 추가할 수 있습니다.

1. [Naver Cloud Platform 콘솔](https://console.ncloud.com) → Service → Application Services → Maps →
   Application에서 애플리케이션 등록
2. 등록 화면에서 **"Dynamic Map"** 옵션을 반드시 체크 (안 하면 브라우저에서 429 Quota Exceed 오류)
3. 이 앱을 실행할 **웹 서비스 URL**(로컬이면 `http://localhost:8788`)을 등록해야 브라우저 인증이 통과됩니다
4. 발급된 **Client ID**를 `backend/.env`의 `NAVER_MAPS_CLIENT_ID=` 뒤에 붙여넣고 서버 재시작

Client ID는 시크릿이 아니라 브라우저 스크립트 태그에 그대로 노출되는 값이라(`/api/config`로
프런트에 전달) 보안은 위 3번의 서비스 URL 등록(도메인 제한)이 담당합니다.

## Vercel 배포

로컬(`npm start`)은 상시 구동 서버지만, Vercel은 서버리스라 요청마다 함수가 뜨고 디스크가 재배포마다
날아갑니다. 그래서 배포 환경에선 캐시(행정동 목록·업종 코드표)와 즐겨찾기를 **Neon(Postgres) DB**에
저장하도록 코드가 이중화돼 있습니다(`backend/lib/cache.js`, `backend/lib/db.js`) — `DATABASE_URL`이
있으면 DB를, 없으면(로컬) 지금처럼 파일 캐시를 씁니다.

### 1) 저장소를 GitHub에 올리고 Vercel에서 Import

이 폴더(`상권분석/`) 전체를 GitHub 리포로 만들고, Vercel 대시보드에서 **Import Project**로 연결하세요.
**Root Directory는 건드리지 마세요**(기본값=저장소 루트) — `api/`, `vercel.json`, 루트 `package.json`이
전부 저장소 루트 기준으로 짜여 있습니다. Framework Preset은 "Other"로 두면 됩니다(정적 빌드 없음).

### 2) Neon(Postgres) 데이터베이스 연결

1. Vercel 프로젝트 → **Storage** 탭 → **Neon** 통합 추가(마켓플레이스에서 바로 생성 가능, 무료 티어 있음)
2. 만든 DB를 이 프로젝트의 **Production/Preview/Development** 환경에 연결(Connect Project)
3. 연결하면 `DATABASE_URL`(및 `POSTGRES_*` 레거시 별칭)이 프로젝트 환경변수에 자동으로 채워집니다 —
   따로 값을 복사해 넣을 필요 없음

첫 요청이 들어올 때 `cache_entries`/`favorites` 테이블을 코드가 알아서 만듭니다(`CREATE TABLE IF NOT
EXISTS`, `backend/lib/db.js`의 `ensureSchema()`) — 마이그레이션 도구나 수동 SQL 실행이 필요 없습니다.

### 3) 나머지 환경변수 등록

Vercel 프로젝트 → **Settings → Environment Variables**에 아래를 추가(로컬 `backend/.env`와 같은 값):

- `SEMAS_SERVICE_KEY` (필수)
- `NAVER_MAPS_CLIENT_ID` (선택, 지도 쓸 때만 — 이 경우 NCP 콘솔의 웹 서비스 URL에 실제 배포 도메인도 등록해야 함)

### 4) 로컬에서 DB까지 붙여 테스트하고 싶다면

Vercel 없이도 [neon.com](https://neon.com)에서 바로 무료 DB를 만들 수 있습니다. 콘솔의 연결 문자열을
`backend/.env`의 `DATABASE_URL=`에 넣고 서버를 재시작하면, 로컬(`npm start`)에서도 캐시가 파일 대신
DB로 가고 즐겨찾기 저장/불러오기가 됩니다. 안 넣으면 지금까지와 동일하게 파일 캐시로 동작하고
즐겨찾기만 "DB 연결 필요" 안내로 대체됩니다 — 둘 다 정상 상태입니다.

### 즐겨찾기와 로그인

지금은 로그인이 없어서 즐겨찾기가 **전부 공용 목록**입니다(이 앱을 쓰는 소수 지인끼리는 서로의
즐겨찾기가 다 보임). 나중에 로그인을 추가하면:

1. `backend/lib/db.js`의 `favorites` 테이블에 `user_id INTEGER` 컬럼 추가
2. `backend/lib/favorites.js`의 세 함수에 `userId` 인자를 받아 `WHERE`/`INSERT`에 끼워 넣기
3. `server.js`의 `/api/favorites` 라우트에서 로그인 세션의 `userId`를 넘겨주기

만 하면 되도록 미리 그 경계로 코드를 나눠뒀습니다.

### 함수 실행 지역을 서울(icn1)로 둔 이유

`vercel.json`의 `"regions": ["icn1"]`은 **지연시간 최적화**입니다. `apis.data.go.kr`는 국내
서버라 서울에서 부르는 편이 Vercel 기본 지역인 `iad1`(Washington D.C.)보다 빠릅니다.

> **주의 — 예전에 이 자리에 "해외 IP가 차단되므로 icn1이 동작 필수 조건"이라고 적혀 있었으나
> 그건 틀린 진단이었습니다.** 첫 배포의 `HTTP 403`은 IP나 리전 문제가 아니라 **Vercel 환경변수에
> 붙여넣은 서비스키가 중간에 잘려 있던 것**이 원인이었습니다(`/health`의 키 지문에서 로컬 102자
> vs 배포 29자로 확인). icn1으로 옮긴 뒤에도 403은 그대로였습니다.
> **해외 리전에서 실제로 되는지 안 되는지는 아직 검증되지 않았습니다.** 지역을 바꿔야 할 일이
> 생기면 "안 될 것"이라고 미리 단정하지 말고 직접 확인하세요.

### 배포 후 403이 뜨면 — 먼저 키부터 대조하세요

`GET /health`가 서비스키의 **길이와 SHA-256 앞 8자리**를 돌려줍니다(키 자체는 노출되지 않음).

```bash
curl -s https://<배포주소>/health
# → {"ok":true,"hasKey":true,"hasDb":true,"key":{"rawLength":102,...,"sha8":"…"}}
```

로컬(`http://localhost:8788/health`)과 **`rawLength`·`sha8`이 같아야** 같은 키입니다. 다르면
붙여넣기가 잘린 것이니, Vercel의 환경변수 값을 **전부 지우고 다시 붙여넣은 뒤 재배포**하세요
(환경변수 변경은 기존 배포에 소급 적용되지 않습니다).

지문이 일치하는데도 403이라면 그때 IP·WAF·활용신청 승인 상태를 의심하면 됩니다.

### 알아두면 좋은 것

- 서버리스 함수는 실행 시간 제한이 있습니다(Vercel Hobby 기본 10초). 지역을 아주 넓게(`maxPages`를
  키워) 조회하면 이 한도에 걸릴 수 있습니다 — `vercel.json`에 `functions` 설정으로 늘릴 수 있습니다.
- 이 배포 구성(루트 `api/`+`vercel.json`+`package.json`)은 **아직 실제 Vercel 프로젝트에 올려서
  검증한 적은 없습니다** — Express-on-Vercel의 표준 패턴을 그대로 따랐고 로컬에서 `VERCEL=1 node
  backend/server.js`로 "listen 안 하고 export만 됨"까지는 확인했지만, 실제 배포 후 라우팅·Neon
  연결까지 확인하려면 한 번 배포해보고 문제가 생기면 알려주세요.

## 무엇이 되고, 무엇이 안 되는지

| 기능 | 상태 |
|---|---|
| 시·도 → 시·군·구 선택 | ✅ 정적 데이터(API 호출 없음, 즉시 반응) |
| 행정동 선택 | ✅ 실API(`baroApi`) 조회, 디스크 캐시 |
| 지역 단위 상권분석 (시·도/시·군·구/행정동) | ✅ 페이지네이션까지 서버가 다 모아 집계 |
| 반경 상권분석 | ✅ 최대 2,000m (API 자체 제한) |
| 업종 대/중/소분류 필터 | ✅ 실API로 코드표를 받아 캐스케이딩 선택 |
| 업종 대분류 분포 / 중분류 Top 15 | ✅ |
| 점포 위치 산점도 (전체 표본) | ✅ (실제 지도 아님 — 좌표 상대 위치, 대분류 상위 3개만 색 구분) |
| 실제 지도(네이버) 위 마커 | ⚠️ `NAVER_MAPS_CLIENT_ID` 설정 시에만. 마커는 최대 1,000개까지만(전체 표본은 위 산점도로) |
| 점포 목록(상호명·업종·주소) | ✅ 클라이언트 필터, 최대 500건 표시 |
| 즐겨찾는 위치 quick-pick | ✅ 대략적 좌표 15곳(강남역·홍대입구역 등), 직접 좌표 입력도 가능 |
| 즐겨찾기(조건 저장/불러오기) | ⚠️ `DATABASE_URL` 연결 시에만. 로그인은 아직 없어서 전부 공용 목록(아래 "즐겨찾기와 로그인" 참고) |
| 프랜차이즈 브랜드 여부 판별 | ❌ 이 API엔 그런 필드가 없음 (상호명 텍스트로 유추 불가) |
| 실시간 유동인구·임대료·매출 추정 | ❌ 이 API가 제공하는 건 "어디에 어떤 업종 점포가 있는지"까지 — 유동인구/추정매출 등은 별도 데이터셋(소진공 상권변화지표 등) |

데이터는 국세청 사업자등록 정보를 기반으로 **분기별** 갱신됩니다. 최근 개업·폐업이 반영되기까지
시차가 있을 수 있습니다 — 이건 API 자체의 한계이지 이 앱의 버그가 아닙니다.

## 코드 구조 메모

- `backend/lib/semasClient.js` — 원본 API 호출. 엔드포인트·파라미터·응답 필드는 전부 공식
  **"소상공인시장진흥공단_상가(상권)정보_OpenApi 활용가이드"(2025.6)** 원문에서 그대로 옮겼습니다
  (추측 아님, 원본 hwp가 이 폴더에 있음). 다만 문서가 개정되거나 서비스가 미세하게 바뀔 수 있으니,
  키를 발급받으면 **`npm run probe`**로 실제 응답을 몇 개 찍어보고 필드 매핑이 맞는지
  한 번 확인하는 걸 권장합니다.
- `backend/lib/regionStatic.js` — 시·도(17개)/시·군·구(252개) 코드는 활용가이드의 "참조. 행정구역
  코드" 표를 그대로 정적 데이터로 박아뒀습니다(자주 안 바뀌어서 API 호출 없이 즉답). 행정동은 개수가
  너무 많고 개편도 있어 `baroApi`로 그때그때 조회합니다.
- `backend/lib/analysis.js` — 상가업소 목록을 업종별 집계·좌표 산점도용 포인트로 정리.
- `backend/lib/landmarks.js` — 반경분석용 quick-pick 좌표. 지오코딩 API(별도 키 필요) 없이 쓰려고
  넣은 대략적 좌표라 정밀 측량값은 아닙니다.
- `backend/data/cache/` — 전부 재생성 가능한 캐시(행정동 목록, 업종 코드표). 지워도 다시 받아지며
  git에는 포함되지 않습니다.
- `frontend/app.js`의 네이버 지도 연동은 `GET /api/config`로 Client ID를 받아 `maps.js` 스크립트를
  동적으로 주입하는 방식입니다. 키가 없으면 지도 카드만 안내 문구로 대체되고 나머지 화면(좌표
  산점도·업종 분포·점포 목록)은 그대로 동작합니다 — 지도는 있으면 좋은 부가 기능이지 필수 경로가
  아닙니다.
- 지역이 넓거나(예: 서울시 전체) 업종을 안 좁히면 점포 수가 많아 표본을 **최대 5,000건**(페이지당
  1,000건 × 5페이지)까지만 가져와 집계합니다. 화면에 "표본 기준" 경고가 뜨면 그 뜻입니다 — 더
  정확한 전체 집계가 필요하면 업종이나 지역 범위를 좁혀서 다시 분석하세요.
